项目定位

AgentGate — 系统层 Agent 行为采集与安全分析网关

AgentGate 位于 Agent 与 AgentMoss 之间，从系统层面收集 Agent 运行数据：它拦截 Agent 与 LLM API 的通信、Agent 的实际命令执行，以及内核层的真实系统调用，归一化后交给 AgentMoss 做应用层安全分析，并可同步返回 Allow/Deny 决策实现实时阻断。

AgentGate 与 AgentMoss 的分工

AgentGate（系统层监控）：采集 Agent「说了什么」（LLM API 意图）、「做了什么」（实际命令）、「真的发生了什么」（内核 syscall），是行为数据的采集与第一道过滤网关。

AgentMoss（应用层监控）：基于 Hook 点的全链路观测，130 条安全规则、PDG 数据流、模型检测，对 AgentGate 上报的行为做深度安全分析并给出 Allow/Deny 决策。

一句话总结

AgentGate = 行为采集 + 语义提取 + 规则过滤 + 实时阻断网关；AgentMoss = 深度安全分析引擎。两者配合形成「系统层采集 → 应用层分析 → 同步阻断」的完整闭环。

🌐

跨平台零侵入

v3 以 LLM API 代理为主路径（mitmproxy），仅需设置 HTTP_PROXY，无需改 Agent 代码、无需 root。适配 Linux / macOS / Windows / WSL2。

🎯

高层语义直接获取

直接解析 tool_calls 的 tool_name + arguments，得到 Agent 的真实意图，而非仅看到系统调用轨迹。

⛔

三级决策 + Fail-Closed

白名单 → 本地快速阻断（403 / kill / 内核阻断）→ AgentMoss 深度分析。AgentMoss 不可用时默认 Deny。

🔒

隐私三模式过滤

auto / cloud_only / local_only 三种模式，正则脱敏 API key、密码、私钥，本地哈希保护敏感凭证。

系统架构

L1 / L2 / L3 三层递进采集模型

AgentGate 从三个层次采集 Agent 行为，语义层次从「意图」到「实际执行」再到「内核真实发生」逐层递进，形成完整证据链。

采集层数据源采集方式语义层次平台
L1 LLM API 通信 mitmproxy 透明代理，解析 OpenAI / Anthropic 协议（含 SSE 流式 tool_calls） 意图层：tool_name + arguments，Agent 主动调用 100% 覆盖 全平台
L2 PTY 进程执行 AgentLauncher 启动子进程，PTY 拦截实际输出命令 执行层：实际运行的命令字符串（如 bash script.sh 内部命令） 全平台
L3 内核 syscall BCC eBPF 加载器，29 种事件类型，PID 白名单 + clone 自动跟踪 事实层：内核真实发生的系统调用（不可篡改） 仅 Linux
为什么以 L1 为主路径？

v2 曾用 eBPF 作为唯一采集源，但存在 WSL2 PID namespace 不匹配、仅 Linux、需 root、语义层低（只知 openat(pathname)，不知意图）四大问题。v3 转向「以 LLM API 语义拦截为主路径，eBPF 为可选增强」，实现跨平台零侵入，同时保留 eBPF 兜底真实执行。

核心流程

PhaseCoordinator 两阶段决策流程

AgentGate 的核心中枢是线程安全的 PhaseCoordinator（async + sync 双接口），将一次 Agent 行为拆分为「采集」与「判断」两个阶段。

📡

Phase 1 · 数据采集

L1 代理解析 tool_calls 后立即上报（不等 L2），保证决策低延迟；L2 事件随后到达，通过 PendingAction 与 L1 融合补充执行细节；L3 事件 fire-and-forget 独立走全量分析管线。

⚖️

Phase 2 · 安全判断

Session 聚合 → 白名单跳过 → 快速阻断规则 → 触发规则（提供精确 severity/risk_type）→ 隐私过滤 → 默认全量送 AgentMoss 三层分析 → 返回 Allow/Deny。

L1 ↔ L2 匹配机制

通过 PendingAction 数据结构按 session_id + tool_name + 时间邻近度匹配 L1 意图与 L2 实际执行，支持 exact/fuzzy 两种匹配，超时自动降级为仅 L1 分析，保证 AgentMoss 上报完整。

同步阻断能力

  • L1 代理层：Deny 时替换响应为 403，Agent 直接收到拒绝
  • L2 进程层：Deny 时 kill 整个进程树
  • L3 内核层：bpf_override_return() 内核级 syscall 阻断（需 CONFIG_BPF_KPROBE_OVERRIDE，不支持时降级 userspace kill_tree）

决策链

白名单 → 快速阻断 → AgentMoss 三级决策

每条触发规则都有明确的动作语义，AgentGate 按优先级逐级决策，高置信度风险在本地秒级拦截，其余交给 AgentMoss 深度分析。

决策级别规则类型动作示例
① 白名单 action: allow + _skip_agentmoss: true 直接放行 不消耗 AgentMoss 安全只读操作、内联脚本假阳性防护
② 快速阻断 action: block + local_block: true 本地秒级阻断 403 / kill / 内核阻断 rm -rf 根目录、chmod 777、curl|bash、反弹 shell
③ 触发分析 trigger_analysis 送 AgentMoss 提供精确 severity/risk_type 敏感文件读写、提权、横向移动、持久化、数据外传
④ 默认全量 未匹配任何规则 送 AgentMoss 三层分析（PDG 数据流 + 行为链 + 模型检测） 任意 tool_call 均上报，构建完整行为上下文
Fail-Closed 语义

AgentMoss 不可用时默认 Deny（区分 timeout / service_unavailable 两类），网关对非预期异常 fail open，避免因监控组件故障放大 Agent 权限。

数据格式

NormalizedEvent 统一事件 Schema

三层采集的事件经归一化后统一为 action / target / payload / process / os_context 结构，AgentMoss 无需感知事件来源层即可直接分析。

{ "event_id": "uuid", "timestamp": { "timestamp_ns": 1700000000000000000, "iso": "2026-05-29T10:00:00Z" }, "source_os": "linux", "source_collector": "llm_api_proxy", // llm_api_proxy | pty | ebpf "session_id": "thread_abc123", "agent_type": "claude-code", "action": { "action_type": "tool_call", "tool_name": "bash", "tool_call_id": "call_xyz", "arguments_raw": "{\"command\":\"rm -rf /tmp/cache\"}" }, "target": { "command": "rm -rf /tmp/cache", "cwd": "", "file_path": "", "arguments": { "command": "rm -rf /tmp/cache" } }, "payload": { "request_model": "claude-sonnet-4-20250514", "request_messages_count": 5, "response_content": "I'll run that command.", "tool_response_content": "command executed", "tool_response_exit_code": 0 }, "process": { "pid": 0, "comm": "", "agent_type": "claude-code" }, "os_context": {} }

AgentMoss 上报格式

AgentGate 将归一化事件打包为 AgentMoss 分析请求：session_id + prompt_session + prompt_history + action_history + a_next + reason + source_layers，其中 source_layers 标注本次判断涉及 L1/L2/L3 中的哪些层，便于 AgentMoss 分层分析。

生态对比

AgentGate vs AgentSight

AgentSight（UC Santa Cruz，eBPF 可观测性框架，参考 eunomia.dev/zh/agentsight）与 AgentGate 同属「系统层 Agent 监控」路线，但定位互补：AgentSight 专注可观测与因果分析，AgentGate 专注行为采集 + 安全阻断。

维度AgentGateAgentSight
定位 行为采集 + 安全分析网关（可阻断） 可观测性框架（仅监控不阻断）
采集核心 L1 LLM API 语义（主）+ L2 PTY + L3 eBPF（可选） eBPF uprobes 拦截 TLS 明文 + tracepoints 捕获 syscall
语义获取 直接解析 tool_calls 意图，100% 覆盖 Agent 主动调用 边界追踪 + 因果引擎（进程谱系 + 时间邻近性 + 参数匹配）
零侵入 设置 HTTP_PROXY 即可，无需 root（L3 除外） 无需改代码；eBPF 捕获需 root / sudo
平台 全平台（L3 仅 Linux） top/bind/report 全平台；record + eBPF 仅 Linux 4.1+
阻断能力 403 / kill 进程树 / bpf_override_return 内核阻断 无（仅观测）
分析联动 对接 AgentMoss 深度分析（PDG / 模型检测 / 130 条规则） 辅助 LLM 语义分析 + OpenTelemetry GenAI 导出
可视化 事件 DB + 日志为主 Web UI：时间线 / 进程树 / 指标视图
性能 代理转发 + JSON 解析，CPU 开销低 优化 eBPF 采集，CPU 开销 <3%
互补关系

AgentSight 的因果追踪（prompt → 行为 → 系统事实的关联）与 Web 可视化，正是 AgentGate 后续可借鉴的演进方向；AgentGate 的同步阻断与 AgentMoss 联动则是 AgentSight 不具备的防御能力。两者可共享 eBPF 采集基础设施，互为补充。

演进路线

后续可演进点

结合 AgentSight 的能力画像与 AARM 三层防御架构，AgentGate 有七个明确的演进方向。

🔗

1. 意图关联与因果追踪

借鉴 AgentSight 因果引擎：以 session_id 为主键建立「prompt 意图 → tool_call 声明 → PTY 实际执行 → syscall 真实发生」的完整证据链，为 AgentMoss 的 L3 关联引擎提供结构化 parentEventIds 数据。

🖥️

2. 跨平台 L3 补齐

macOS 可用 Endpoint Security Framework (ESF) / DTrace，Windows 可用 ETW 替代 eBPF，补齐 TS 版缺失的 L3 能力，实现「声明 → 执行 → 事实」三层全平台覆盖。

📊

3. 可视化与会话回放

对标 AgentSight 的时间线 / 进程树 / 指标三视图，建设 AgentGate Dashboard：行为时间线回放、会话级事件流查看、阻断事件高亮，提升攻防演示与取证效率。

📤

4. 标准遥测导出

参照 AgentSight 的 OpenTelemetry GenAI span 导出，将捕获的 LLM 调用转为 gen_ai.* 标准 span（OTLP/HTTP），无缝接入企业可观测性平台。

⚡

5. 性能与延迟优化

SSE 流式响应改边收边解析（当前缓冲完整响应）；连接池 / 异步 IO；与 AgentSight 的 <3% CPU 开销对标，量化网关转发开销。

👥

6. 多 Agent 关联与策略 DSL

多 Agent 协作场景的跨会话关联（共享文件 / 共享凭证 / 事件因果链）；将 YAML 规则升级为更丰富的策略 DSL，支持条件组合与上下文敏感策略。

7. 语义分析批量化（L1 网关侧预判）

在网关侧对 tool_calls 做低成本语义预判（如 prompt 注入模式、敏感参数扫描），仅对可疑行为触发 AgentMoss 全量分析，降低 AgentMoss 分析负载与响应延迟——这是从「全量上报」走向「分级上报」的关键演进。
