系统架构

双层安全检测模型

AgentMoss 采用双层安全检测模型，第一类快速单点检测零时延覆盖已知威胁模式，第二类全链路行为分析捕获组合安全威胁。

关键洞察：组合威胁

有些行为单独看是安全的，但组合起来构成威胁。行为 A: 读取 .env 文件 → L1 检测: allow ✅；行为 B: POST 到外部 URL → L1 检测: allow ✅；A;B 组合: 凭证外泄 → L2.1 PDG 检测: BLOCK 🚨

事件管道

事件管道流程

干预 Hook 同步执行阻断，观察 Hook 异步采集分析，两类 Hook 协同构建完整安全监控链路。

L1 同步

干预 Hook（同步检查+阻断）

before_tool_call 等干预类 Hook 同步执行，第一类正则规则 + 第二类 PDG 评估，返回 block / allow / requireApproval。

  • before_tool_call → 工具调用策略检查
  • message_sending → 凭证泄露检测
  • tool_result_persist → 扩展密钥+注入检测
  • subagent_spawning → 凭证外发检测
  • before_install → 安装安全扫描
L2 异步

观察 Hook（异步事件记录）

观察类 Hook 异步采集事件，进行事件标准化、存储写入、行为图/PDG 增量更新、全局关联分析、SSE 广播。

  • llm_input / llm_output → 模型输入输出
  • after_tool_call → 工具结果观察
  • session_start/end → 会话生命周期
  • message_received/sent → 消息流
信任模型

数据信任模型

AgentMoss 为每个事件标注来源信任级别（SourceTrust），用于安全 PDG 的完整性评估。

信任级别来源完整性评估
systemAgent 运行时自身高 — 系统生成，可信
user用户直接输入高 — 来自信任通道
llm大模型输出中 — 可能被 Prompt 注入篡改
tool工具执行结果低 — 外部系统输出，不可信
external外部内容/网络低 — 不可控来源
核心组件

六大核心引擎

从事件摄入到安全决策，六大引擎协同工作，构建完整的 Agent 行为安全监控链路。

📡

Event Ingest Pipeline

事件摄入管道，防御过滤（丢弃 assistant 流噪声，事件量减少 ~90%），事件标准化，存储写入。

源文件： src/ingest/

🔍

Policy Engine

策略引擎，L1 单点行为规则核心。91 条正则规则，覆盖 12 个 ATLAS Tactic。零时延同步返回 block/approval 决策。

源文件： rules.ts · hooks.ts · behavior-chain.ts

🧬

Security PDG

安全程序依赖图，L2.1 数据流检测核心。基于 AgentArmor 论文实现 PDG 图构建 + 安全标签格传播 + 16 条违规检测规则 + 行为链 7 条 + 全局关联 1 条。

源文件： pdg.ts (1090行) · registry.ts (359行)

🔗

Graph & Correlation

行为图构建 + 证据链追溯 + 全局关联分析。CFG 控制流可视化，跨会话攻击链检测。

源文件： src/graph/ · src/correlation/

🖥️

Web Dashboard

SSE 实时推送 + 三栏布局仪表盘。6 个视图：全链路行为、单点检查、工具监控、Skill 监控、Token 分析、风险事件。

源文件： src/ui/

💾

Storage Layer

存储层支持 Memory（开发调试）和 SQLite+JSONL（生产部署）。运行标题智能推导。

源文件： src/store/
