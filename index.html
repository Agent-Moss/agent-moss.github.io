概览

为什么需要 AgentMoss

AI Agent 拥有执行 shell 命令、读写文件、发送网络请求等高权限能力。一旦被 Prompt 注入攻击，Agent 可能被诱导执行破坏性操作或泄露敏感数据。AgentMoss 在 Agent 运行时旁边架设监控，不侵入 Agent 逻辑，实时检测并阻断危险行为。

🛡️

不侵入 Agent 逻辑

纯观测式插桩（side-channel），通过 Agent 运行时提供的 Plugin Hook 点采集事件，Agent 核心执行路径零修改。

🔒

Fail-Closed

监控服务不可用时自动阻断危险操作，避免安全系统失效后静默放行。确保安全监控的可靠性。

🏗️

纵深防御

L1 单点检测 + L2 行为链 + L3 PDG 数据流 + L4 全局关联，四层检测互补，覆盖从单条命令到跨会话攻击链。

⚡

实时干预

第一类检测零时延（单事件即时判断 <100ms），第二类检测异步分析。PDG 桥接两层，实现异步分析结果同步阻断。

📊

全链路可观测

SSE 实时推送、Web Dashboard 行为树可视化、证据链追溯、Token 用量统计。每个安全决策附带完整证据路径。

🔧

多运行时适配

当前适配 OpenClaw 运行时，通过 Adapter 机制支持 Hermes、JiuWenClaw 等其他 Agent 运行时。

系统架构

双层安全检测模型

关键洞察：组合威胁

有些行为单独看是安全的，但组合起来构成威胁。行为 A: 读取 .env 文件 → L1 检测: allow ✅；行为 B: POST 到外部 URL → L1 检测: allow ✅；A;B 组合: 凭证外泄 → L3 PDG 检测: BLOCK 🚨

事件管道流程

L1 同步

干预 Hook（同步检查+阻断）

before_tool_call 等干预类 Hook 同步执行，第一类正则规则 + 第二类 PDG 评估，返回 block / allow / requireApproval。

  • before_tool_call → 工具调用策略检查
  • message_sending → 凭证泄露检测
  • tool_result_persist → 扩展密钥+注入检测
  • subagent_spawning → 凭证外发检测
  • before_install → 安装安全扫描
L2 异步

观察 Hook（异步事件记录）

观察类 Hook 异步采集事件，进行事件标准化、存储写入、行为图/PDG 增量更新、全局关联分析、SSE 广播。

  • llm_input / llm_output → 模型输入输出
  • after_tool_call → 工具结果观察
  • session_start/end → 会话生命周期
  • message_received/sent → 消息流

检测方法

五层混合检测体系

从单条命令的模式匹配到跨会话攻击链的关联分析，五层检测互补覆盖，逐层提升绕过难度。

层级方法说明绕过难度

L2行为链检测 (Behavior Chain)跨步骤时序序列分析（download→execute, download→persist）中
L3PDG 数据流 (Data Flow)基于污点传播的高敏感数据流向追踪，正则打标签→图论标签传播→拓扑违规判定较高
L4全局关联 (Cross-Run)跨 runId/session 多会话攻击链分析高
L5语义意图 (Semantic)LLM 辅助意图解析（规划中）最高

PDG 检测还是模式匹配吗？

结论先行

不是纯模式匹配，而是"正则打标签 → 图论标签传播 → 拓扑违规判定"的三层混合机制。正则只在第 1 层用于标记节点属性，真正的检测能力来自第 2 层标签传播和第 3 层图拓扑分析。

第 1 层：正则打标签 (Labeling) 第 2 层：图论标签传播 (Propagation) detectSensitiveKinds() / hasPromptInjection() joinConfidentiality() = max(a, b) → 给每个 PDG 节点赋予 confidentiality/integrity/ joinIntegrity() = min(a, b) sensitiveKinds 初始安全标签 sensitiveKinds = 并集 → 沿数据依赖边传播标签 第 3 层：拓扑违规判定 (Inspection) inspectSecurityPdg() — 16 条规则 → 标签比较 / 边类型检查 / BFS 遍历 / 数据源计数 / 兄弟节点对比 → 安全决策

第 3 层使用 6 种拓扑分析方法：标签比较、边类型检查、BFS 遍历、数据源计数、兄弟节点对比、参数内容匹配（仅用于精确化降级误报）。正则在 PDG 中不是"检测引擎"，而是"标签器"——检测决策完全由图拓扑分析完成。

安全标签系统

每个 PDG 节点携带一个 SecurityLabel，包含四个维度的安全属性：

type SecurityLabel = { confidentiality: "low" | "medium" | "high"; // 机密性 integrity: "low" | "medium" | "high"; // 完整性 sensitiveKinds: string[]; // 敏感类型标签 actionClass: SecurityActionClass; // 操作分类 };
维度取值语义
Confidentialityhigh / medium / low检测到 API Token、密码、私钥、.env、PII → high；工具输出 → medium；其他 → low
Integrityhigh / medium / lowsystem/user → high；llm → medium；tool/external → low（含注入则强制 low）
sensitiveKinds数组api_token, credential, private_key, dotenv_secret, pii_financial, prompt_injection
actionClass枚举read, write, network_egress, message_egress, compute, unknown

格传播规则 (Lattice Propagation)

基于安全格理论，沿数据依赖边传播标签。机密性取高（高处流原则），完整性取低（低处流原则）。

机密性取 max（高处流原则）

一个节点只要从任何一条路径接收到高机密数据，该节点就应被视为高机密。

完整性取 min（低处流原则）

一个节点只要从任何一条路径接收到低完整性数据，该节点就应被视为低完整性——不可信数据"污染"了下游。

// 机密性合并：取最高级别 joinConfidentiality(left, right) = confidentialityRank[left] >= right ? left : right; // 完整性合并：取最低级别 joinIntegrity(left, right) = integrityRank[left] <= right ? left : right; // 敏感类型合并：取并集 sensitiveKinds = unique([...left, ...right]);

传播路径：Parent OBS → Child UP/SP（注入检测关键路径）、Parent OBS/D → Child TP（数据外传检测关键路径）、Parent LLM → Child T（控制流依赖）等。

AARM 框架

三层防御架构

AgentMoss 是 AARM (Agent Armor Runtime Monitor) 框架的 TypeScript 独立版本，与 Python 版本和 Kernel 层检测系统共同构成完整的三层防御架构。

防御层组件检测粒度关键能力
L1 Hook AgentMoss (TypeScript) 命令行字符串 rm -rf / ✅、PDG 数据流 ✅、bash script.sh ❌
L2 Kernel secDetector (openEuler) syscall execve/unlink 穿透脚本 ✅、实时阻断 ✅、不理解意图
L2.5 语义 AgentSight (eBPF) TLS意图+syscall行为 因果关联 ✅、语义理解 ✅、不阻断
L3 关联 AARM 关联引擎 parentEventIds Hook+Kernel+语义 → 完整证据链

AgentMoss (TS)

AARM 框架 TypeScript 独立版本，~6800 行代码。Hook 监控方案，不依赖特定 Agent 框架。AgentArmor 论文方法已部分实现。

AgentMoss (Python)

AARM 框架 JiuwenSwarm 旁路扩展版本，3520 行 Python。双模式接入：Extension Hook 回调 + DeepAgent Rail 旁路 patch。

secDetector

openEuler 内构入侵检测系统。内核级 syscall 监控，穿透脚本黑箱，检测 bash script.sh 内含 rm 等间接调用。但不理解 LLM 意图。

AgentSight
