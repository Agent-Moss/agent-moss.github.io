检测方法

三层检测体系

AgentMoss 采用三层检测架构：L1 单点行为规则提供快速初筛，L2 长行为链规则通过 PDG 和模型检测捕获组合威胁，L3 语义规则（规划中）将引入 LLM 辅助意图分析。

层级规则类型分析方法说明状态
L1 单点行为规则 模式匹配 (Pattern Match) 基于正则的单步静态检测，fast-path 初筛，91 条规则 已实现
L2 长行为链规则 L2.1 基于PDG 程序依赖图拓扑分析 + 行为链时序 + 全局关联，24 条规则 已实现
L2 长行为链规则 L2.2 模型检测，时序规则 基于时序逻辑的模型检测，自动验证行为序列合规性 已实现
L3 基于语义的规则 LLM 辅助意图解析 语义意图分析，理解 "为什么" 而非 "是什么" 待添加
层级关系

L1 是快速初筛层，零时延覆盖已知威胁模式。L2 是深度分析层，通过 PDG 数据流追踪和行为链时序检测组合威胁，L2.2 将引入模型检测覆盖更复杂的时序规则。L3 是语义理解层（待添加），通过 LLM 理解 Agent 行为的真实意图，解决 L1/L2 无法区分合法操作与攻击的根本问题。

L1

L1 单点行为规则

91 条正则规则覆盖 12 个 ATLAS Tactic，零时延同步返回 block/approval 决策。阻拦 (block) 24 条，询问 (approval) 67 条。

检测方法

基于正则表达式的单步命令行字符串匹配。fast-path 初筛，无上下文依赖，无 Token 消耗。

优势

  • ✅ 零延迟（<1ms）
  • ✅ 零外部依赖
  • ✅ 覆盖已知威胁模式
  • ✅ 误报风险已治理（44 条降级为 approval）

局限性

  • ❌ 无上下文感知
  • ❌ 无变量展开追踪
  • ❌ 无脚本内容检测
  • ❌ 对抗性绕过（编码变体、前缀包裹等）
L2

L2 长行为链规则

L2 层关注跨步骤、跨事件的长行为链检测，包含两种分析方法。

L2.1

基于 PDG（已实现）

将 Agent 运行时轨迹建模为程序依赖图（PDG），通过图拓扑分析检测数据流违规。包含三种检测子方法：

  • 行为链检测 — 7 条预定义攻击链（download→execute 等）
  • PDG 数据流检测 — 16 条违规规则（敏感数据外传、注入检测等）
  • 全局关联 — 1 条跨会话攻击链规则

合计 24 条规则 · 源文件: behavior-chain.ts · pdg.ts · global-analyzer.ts

L2.2

模型检测，时序规则（已实现）

基于时序逻辑（LTL/CTL）的模型检测方法，自动验证 Agent 行为序列是否满足安全属性。相比 L2.1 的预定义模式：

  • ✅ 自动发现未知攻击链模式
  • ✅ 无需人工定义行为链序列
  • ✅ 可验证复杂时序约束（G/F/X/U 算子）
  • ✅ 支持分支路径分析（CTL 路径量词 A/E）

15 条规则（10 LTL + 5 CTL） · 源文件: model-checker.ts · mc-rules.ts · state-machine.ts · temporal-logic.ts

L2.1 与 L2.2 的互补关系

L2.1 基于预定义模式和图分析，能精确检测已知攻击链。L2.2 基于模型检测，能自动发现满足/违反时序属性的未知攻击模式。两者互补覆盖已知和未知的长行为链威胁。

L2.1 深度解析

PDG 三层混合机制

PDG 检测不是纯模式匹配，而是"正则打标签 → 图论标签传播 → 拓扑违规判定"的三层混合机制。

结论先行

正则只在第 1 层用于标记节点属性，真正的检测能力来自第 2 层标签传播和第 3 层图拓扑分析。

层方法核心代码是否为模式匹配
第 1 层正则打标签 (Labeling)detectSensitiveKinds / hasPromptInjection是（仅用于初始化标签）
第 2 层图论标签传播 (Propagation)joinConfidentiality = max / joinIntegrity = min否（图论格运算）
第 3 层拓扑违规判定 (Inspection)inspectSecurityPdg — 16 条规则否（图结构分析）

第 3 层使用 6 种拓扑分析方法：标签比较、边类型检查、BFS 遍历、数据源计数、兄弟节点对比、参数内容匹配（仅用于精确化降级误报）。正则在 PDG 中不是"检测引擎"，而是"标签器"——检测决策完全由图拓扑分析完成。

L2.2 深度解析

模型检测机制

将 Agent 事件序列建模为 Kripke 结构，使用 LTL 检测线性时序攻击模式和 CTL 验证分支安全属性。

核心思路

LTL 规则检测攻击模式：公式满足 = 攻击存在。CTL 规则验证安全属性：属性违反 = 攻击存在。两种逻辑互补覆盖线性时序和分支路径。

逻辑用途检测方式算子
LTL攻击模式检测公式满足 = 攻击存在G (全局) · F (最终) · X (下一) · U (直到)
CTL安全属性验证属性违反 = 攻击存在AG · EG · AF · EF · A[U] · E[U]

Kripke 结构构建

K = (S, S₀, R, L) // S: 状态集（每个事件=一个状态） // S₀: 初始状态（最早的事件） // R: 转移关系（时间顺序 / parentEventIds） // L: 标记函数 → Set<原子命题>

标记函数 labelEvent() 复用 L1 正则模式和 PDG 内容分析，为每个状态分配 17 种原子命题（reads_credential、network_egress、execute_file、prompt_injection 等）。

安全标签

安全标签系统

每个 PDG 节点携带一个 SecurityLabel，包含四个维度的安全属性。

type SecurityLabel = { confidentiality: "low" | "medium" | "high"; // 机密性 integrity: "low" | "medium" | "high"; // 完整性 sensitiveKinds: string[]; // 敏感类型标签 actionClass: SecurityActionClass; // 操作分类 };
维度取值语义
Confidentialityhigh / medium / low检测到 API Token、密码、私钥、.env、PII → high；工具输出 → medium；其他 → low
Integrityhigh / medium / lowsystem/user → high；llm → medium；tool/external → low（含注入则强制 low）
sensitiveKinds数组api_token, credential, private_key, dotenv_secret, pii_financial, prompt_injection
actionClass枚举read, write, network_egress, message_egress, compute, unknown
格传播

格传播规则 (Lattice Propagation)

基于安全格理论，沿数据依赖边传播标签。机密性取高（高处流原则），完整性取低（低处流原则）。

机密性取 max（高处流原则）

一个节点只要从任何一条路径接收到高机密数据，该节点就应被视为高机密。

完整性取 min（低处流原则）

一个节点只要从任何一条路径接收到低完整性数据，该节点就应被视为低完整性——不可信数据"污染"了下游。

// 机密性合并：取最高级别 joinConfidentiality(left, right) = confidentialityRank[left] >= right ? left : right; // 完整性合并：取最低级别 joinIntegrity(left, right) = integrityRank[left] <= right ? left : right; // 敏感类型合并：取并集 sensitiveKinds = unique([...left, ...right]);

传播路径：Parent OBS → Child UP/SP（注入检测关键路径）、Parent OBS/D → Child TP（数据外传检测关键路径）、Parent LLM → Child T（控制流依赖）等。
